# 人员创建的用户名边界修复

日期：2026-10-27。目标用户为维护员工、部门主管档案的管理员。本轮解决人员管理入口的用户名长度与自动占位邮箱冲突，保留现有Vue、Spring Boot、MySQL和身份权限体系。

## 问题与范围

流程为管理员提交人员资料和初始密码，经操作权限检查后，在同一事务内创建账号及关联档案。现有服务允许非空且最多64字符的用户名；但AccountLifecycleService把用户名直接拼接成`username@example.invalid`，后缀16字符，用户名达到15字符时会超过邮箱30字符限制。中文、含`@`等现有允许用户名也不应被占位邮箱生成方式意外限制。

数据库schema、升级夹具和H2测试schema的邮箱列都是`varchar(30) NOT NULL`，账号及邮箱分别具有包含deleted状态的唯一约束。邮箱参与登录别名、个人资料及管理员导出；当前没有实际邮件通知或邮箱找回流程，不能仅为这次创建问题放宽所有真实邮箱规则。

本轮仅修改人员创建共用的自动占位邮箱：生成与用户名无关的短随机别名，保留`@example.invalid`，总长度30字符。用户名完整保存，既有账号及邮箱不重写；不改变密码、UID、角色、权限、人员资料接口或数据结构。地址唯一性继续由现有服务检查及数据库唯一约束执行，冲突按创建失败处理，不覆盖已有账号，不增加自动重放写入。

## 验收与验证方案

- 员工与主管分别通过MockMvc进入真实MVC控制器、Service和H2 SQL创建；14、15及64字符用户名和既有允许字符完整保存，账号与档案关联、部门、角色和密码哈希正确，随后可用用户名或占位邮箱登录。
- 共同长前缀、末位不同的账号都可创建，占位邮箱互不相同，防止用截断用户名掩盖问题。
- 65字符及重复用户名继续拒绝，账号和档案无额外写入；已有档案写入抛错时账号回滚的测试继续通过。
- 员工、主管即使拥有菜单操作权限也不能创建人员；管理员缺对应新增权限同样拒绝，且无写入。
- 先证明新增回归能检出原错误，再验证修复；本机使用项目test profile及H2内存库，CI继续验证MySQL建库与迁移。禁止连接或修改使用方原始数据库。
