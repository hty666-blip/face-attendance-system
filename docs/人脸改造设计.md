# 本地人脸识别改造

日期：2026-10-23。目标用户为员工与负责人员档案的管理员。

主流程：管理员在员工档案中采集三张照片 → 本地服务检查唯一人脸与质量并提取特征 → Java 加密保存模板及版本 → 员工打开打卡弹窗获取一次性会话 → 本地服务验证本人 → Java 按现有规则生成考勤。

首版范围：CPU 上的 YuNet + SFace 推理、三张样本采集、质量失败提示、模板状态与撤销、旧照片逐人迁移、本人 1:1 验证、会话时效与重复提交保护、腾讯云显式可选配置、日志及可重复启动。

非目标：训练模型、宣称企业级识别精度、活体检测、复杂班次、位置防伪、通过 AI 修改考勤。一次性会话只能防止同一请求重复执行，不能证明摄像头前是真人。

## 权责与数据

- Java 保有账户、权限、模板登记与撤销、事务、业务规则、考勤及验证会话；Python 不连接数据库、不接受浏览器直接调用、不持久化照片或特征。
- Python 只做人脸检测、对齐、特征提取和余弦相似度计算。Java 独立检查 Provider、模型版本、模板版本和阈值，避免让外部响应直接决定落库。
- 本地默认 Provider，不在故障时上传到腾讯云。切换 Provider 必须显式配置；不同 Provider 的模板不互用，旧照片迁移需要管理员发起。
- 新模板使用 AES-256-GCM 加密并绑定用户、Provider、模型和模板版本；加密密钥独立于登录签名密钥。撤销/重新录入递增版本，使旧打卡会话失效。
- 旧 `sys_user.face` 不自动批量转换；管理员确认迁移成功后清除该用户旧明文照片。迁移前应备份原库，质量不合格则要求重新采集。
- 需要两个新表：加密模板与打卡验证会话。通过 V002 迁移，不自动修改已有数据库。

## 执行边界

采集只对管理员开放；员工只能读取本人录入状态。打卡会话绑定当前登录者、模板版本、Provider、有效期和请求指纹。成功请求重试返回原记录编号，不能重复写考勤；失败或过期后获取新会话。并发提交只有一个执行者；服务中断后未完成会话不放行，超时后可重新发起。

模型文件锁定官方来源与 SHA-256，首次准备时下载，运行时离线。Python 仅监听回环地址，内部接口使用独立服务令牌。请求限制图片大小、像素和数量，推理串行且超额快速拒绝，避免无界队列。日志不记录图片、特征、密钥或访问令牌。

## 验收

1. 无云人脸凭据时，本地真实模型能够完成公开测试样本的检测、特征提取及同图比对；该检查不当作人群准确率评测。
2. 无人脸、多人脸、低质量、损坏图片、模型缺失、服务不可达有明确错误且不写考勤。
3. 撤销和重新录入使旧会话失效，匿名/其他员工不可替换模板，不同用户的模板密文不可互换。
4. 同一成功会话重试及并发提交不重复写考勤；数据库写入失败时考勤与会话成功状态一起回滚。
5. 摄像头拒绝授权、设备缺失、晚到的授权结果、关闭与页面卸载均能正确结束视频轨道；关闭后不继续占用摄像头。
6. Java、Python、前端构建与针对性测试通过；公开仓库不包含照片、特征、模型权重或本机凭据。

参考：[OpenCV 检测与识别教程](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)、[YuNet 模型与许可](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)、[SFace 模型与许可](https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface)。质量参数与匹配阈值均为可调整初值，需要用自愿采集的独立测试集校准。
