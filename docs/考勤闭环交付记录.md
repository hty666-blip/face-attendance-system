# 固定日班考勤闭环交付记录

日期：2026-10-26。对应设计为《考勤闭环设计.md》，在已有基础修复及本地人脸识别之上完成。保留 Vue 3、Spring Boot 2.7、Java 8 语言目标及 MySQL；构建验证使用 JDK 17。

## 交付范围

员工可以选择签到或签退扫脸，在月度工作台查看每日结果，提交过去缺卡的补卡申请及日期化的日/半日请假。主管按权限审批他人申请，员工可以撤回待审批申请；详情保留每次状态历史。管理员追加未来生效的全组织日班规则、维护未来工作日。今天未完成动作显示进行中，过去缺卡显示待核对，不直接判定旷工。

每人每天每种动作至多一个事件。人脸会话绑定本人、业务日、动作及模板版本，写入前重新验证窗口和动作唯一性。补卡批准新增 CORRECTION 事件，分别保存发生时间和写入时间；原始事件不可直接增改删。半日以12:00分界，批准上午假免签到、下午假免签退，待审批申请不抵扣。

申请创建使用 requestKey 及内容哈希，状态更新使用版本校验和用户行锁；申请、补卡事件和状态历史在同一 Java 事务内提交。相同申请或相同决策的重试返回已有结果，矛盾内容或过期版本返回冲突。前端遇到未知结果保留原请求内容和版本，避免生成另一份申请。

## 请求链路与设计取舍

1. 扫脸：浏览器查询当天可用动作 → Java 创建绑定动作的会话 → Java 调用本地 Python 推理 → Java 再次校验业务规则 → MySQL 保存事件并完成会话。Python 只负责图像与特征计算，不访问业务数据库。
2. 申请：浏览器提交确定的日期、半日或补卡时间 → Java 根据登录身份推导申请人和部门，检查范围/重叠/权限 → 保存申请及创建历史。
3. 审批：主管读取有权查看的待办及历史 → Java 复查当前人员范围、申请当时部门、版本及不可自审规则 → 更新状态，必要时写补卡事件，追加审批历史。
4. 月结果：读取单月日快照、原始事件和批准的请假事实 → Java 即时计算结果。审批后重新查询即可看到变化，无需等待异步汇总刷新。

全局固定日班足以完成本阶段业务，不增加排班服务、队列或汇总缓存。过去/当天保留规则快照，未来读取不冻结快照，避免规则改动悄悄改写过去或阻碍未来调整。AI 尚未接入，后续通过现有权限和业务服务调用工具，不另建一套审批规则。

新事件与申请保存部门。主管访问同时受当前人员范围及历史部门约束；调入人员不会因此开放原部门历史。过去没有可靠归属的日不猜测原部门，相关申请归属0，只允许管理员复核。原始事件列表、导出和旧事件统计共用可见范围；旧统计明确标注事件条数或旧申请条数，不冒充新日结月报。

## 数据库启用与恢复

- 新空库执行 `database/schema.sql`、`database/seed.sql`，不再重复迁移。既有库先备份，在副本核对后按 V001、V002、V003 顺序只执行缺少的脚本；已是 V002 的库仅执行 V003。
- V003 将执行当日作为新口径生效日，使用 +08:00 数据库会话时区，初始日班复制旧规则。执行前确认旧规则开始早于12:00、结束晚于12:00，并核对连接库名、备份恢复及主管授权。自定义角色不会被批量授予补卡审批权限。
- 旧事件的动作/业务日保持空，不猜测转换；旧自由时长请假保留读取、旧审批及合规撤回，不计入新半日假。旧未完成扫脸会话失效，客户端须获取新会话。
- 迁移不由应用启动自动执行。MySQL DDL 存在隐式提交；恢复依赖数据库备份及相匹配的代码版本，单纯回退代码不能恢复规则、事件或申请状态。不要在现有库重复导入新建脚本。人脸模板密钥仍需与数据库安全备份。

## 演示步骤

1. 按 README 用新空库启动服务并初始化管理员；创建合成部门、主管及员工，核对角色权限，由管理员为自愿参与者采集三张人脸。
2. 员工在当天动作窗口内选择签到或签退、定位并扫脸，查看原始事件及月度日结果。重复原成功请求应返回同一记录，另一个会话不能重复同日同动作。
3. 员工选择允许范围内的日/半日请假并提交；主管打开待办，查看原因与历史后批准。员工刷新，确认请假天数及对应动作豁免变化。另以待审批申请演示撤回。
4. 对新口径生效后已经过去且缺卡的工作日申请补卡，主管批准后查看 CORRECTION 来源及日结果变化。首次启用当日没有这种历史日，应等待次日，或只在明确标为合成的隔离演示库构造历史时序。
5. 管理员追加未来规则或调休日期，确认今天及过去快照保持原值。用另一部门账号验证看不到申请及不可见历史事实。

可在准备好账号与数据后用5～10分钟演示核心闭环。演示账号、照片、密钥和数据库内容不应提交到公开仓库。

## 已知限制与下一阶段

当前只有全组织固定日班，不支持跨夜、多班次、部门差异排班、小时假、工资或加班结算。没有私密附件存储、通知系统及完整月度报表中心；现有原始事件导出与旧统计不能代替完整月报。

人脸检测、识别阈值及质量阈值仍为工程初值，未做人群校准；尚无活体检测和可靠位置防伪。腾讯云仅保留显式兼容配置，未调用原云账号验证有效性。本轮未执行生产部署、原库迁移或真实企业验收。

下一阶段优先建立与当前日结果同口径、同权限范围的月度报表与导出，再接入 AI 查询和受控操作工具。
