# DeepSeek 接入交付记录

日期：2026-10-27。目标用户为需要通过自然语言查询本人考勤、生成有权查看的部门月报的员工和主管。本轮在用户填写本机 API Key 后，将已有 LangChain 工具计划链路连接到真实 DeepSeek 服务，并用独立合成环境验证两条完整业务。原有 Vue、Spring Boot、MySQL 和本地人脸能力继续保留。

## 范围与验收目标

本轮验收“真实模型选择工具，Java 按当前身份执行，页面或接口取得可核对的真实业务结果”。具体完成本人月度汇总、主管所属部门月报导出，验证与直接报表一致、重复请求只生成一个任务、其他用户不能读取运行或下载文件。真实请求只使用两个部门、五个合成账号及人工构造的请假和补卡记录，没有连接或改动使用方原始数据库，没有发送真实人脸、真实员工资料或原始数据库内容。

已有单日解释和导出状态工具继续保留，但本次短样本没有对这两项发起真实模型请求。没有增加 AI 请假、补卡、审批、任意 SQL、任意 HTTP、命令执行或公开部署，也没有开展完整模型准确率评测。

## 模型参数及兼容处理

本机私密配置采用以下参数，API Key 由用户填写并保留在被 Git 忽略的 `.local` 文件中：

| 项目 | 本轮配置与理由 |
| --- | --- |
| Provider | `openai-compatible`，复用已实现的 `ChatOpenAI` 和 LangChain 结构化工具链路 |
| 模型 | `deepseek-flash`；核对日官方模型表列出该名称及工具调用支持，本轮无需更换已有编排框架 |
| 服务地址 | `https://api.deepseek.com/beta`，匹配官方 `strict` 工具调用要求；每个 function 保持 `strict=true` |
| 思考开关 | `thinking={"type":"disabled"}`；本业务只需短结构化工具建议和有限澄清，沿用项目不保存模型思维内容的约定 |
| 输出预算 | 每次 `max_tokens=600`，属于本项目设置的短输出上限，不是模型的最大能力或平台默认值 |
| 重试与并行 | SDK `max_retries=0`、`parallel_tool_calls=false`，保留应用已有超时及单工具响应约束 |

官方工具文档要求使用 `/beta` 地址并为工具声明 `strict=true`，服务端校验工具的 JSON Schema。项目仍执行 Python 参数校验和 Java 再鉴权，不能把格式约束当作业务权限。[DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

官方说明可以通过 `thinking` 控制思考模式，并通过 `extra_body` 传递此参数。本项目针对精确主机 `api.deepseek.com` 显式关闭思考，将 `thinking` 与 `max_tokens` 放入请求正文；这样保留 DeepSeek 接口所需的 `max_tokens` 名称，避免当前 SDK 将其改名产生兼容问题。其他兼容服务保持原有参数路径。[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

`deepseek-flash` 的有效模型和计费规则以官方当前页面为准。本轮只记录服务返回的 token 用量，没有读取账户账单，也没有将 token 数折算成实扣费用。[DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)

## 请求链路与身份边界

浏览器或验收客户端使用登录态向 Java 创建会话，再发送 `POST /assistant/runs`，包含会话编号、固定 `requestKey` 和自然语言问题。Java 从当前登录账号取得身份、权限和部门选项，向 Python 的 `POST /assistant/v1/plan` 发送有限上下文。Python 经 LangChain 调用 DeepSeek，返回一个工具建议；Java重新校验当前身份、参数、权限和执行预算，再调用已有报表或导出 Service，持久化运行和工具回执。

工具执行后，Java 将安全回执交给下一次计划请求，直到模型不再建议工具。本次两条业务各使用两次外部模型请求：一次选择工具、一次结束轮次。统计数字、任务编号及实际成功状态由 Java 根据回执生成，不采用模型自由文本替换业务事实。

API Key 只交给 Python 模型调用进程；Java只需要启用开关、`openai-compatible` Provider、Python 内部地址及独立内部令牌。模型不持有用户 JWT、不访问 MySQL、不回调 Java，也不能自行指定调用地址或可信部门范围。内部令牌不进入提示词、浏览器或导出文件，外部 LangSmith 追踪保持关闭。

## 可重复启动与私密配置

已准备依赖及内部令牌后，可在项目目录启动能力服务：

```powershell
.\scripts\start-ai.ps1 -ModelConfigPath .local/deepseek.ps1
```

`ModelConfigPath` 只接受本项目 `.local` 内的普通 UTF-8 配置文件。加载器将其解析为数据，只允许白名单中的单引号静态环境变量赋值；拒绝脚本命令、表达式、重复字段、越界路径、重解析链接、无效地址和启用外部追踪的配置，不执行文件内容。启动期间临时注入模型配置，正常退出或启动失败时恢复原进程环境。

Java 与 Python 使用相同的 `ASSISTANT_INTERNAL_TOKEN`。Java侧配置 `ASSISTANT_ENABLED=true`、`ASSISTANT_PROVIDER=openai-compatible` 和对应 `ASSISTANT_URL`，不加载模型 Key 文件。常规启动方式仍需要明确的业务数据库配置；本轮验收采用单独新建的临时合成数据库，没有使用原始数据库进行试连。

独立演示入口 `scripts/start-demo.ps1` 继续强制 Mock，不读取或继承模型 Key；其“合成演示、非真实 AI”说明保持有效。本轮真实验证使用单独的本地启动器和新运行目录，复用资源身份检查与安全回收 helper，没有改变演示环境的凭据隔离契约。
