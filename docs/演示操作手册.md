# 本地合成演示操作手册

日期：2026-10-27。面向作者、评审者和首次复现者。依赖已准备好后，下面的业务演示约需5～10分钟；启动服务的等待时间另计。

本入口使用全新的本机临时MySQL容器、两个合成部门及管理员/主管/员工三类角色。人脸关闭；历史事件来自真实补卡审批，来源为`CORRECTION`。助手明确使用Mock规则解析，查询、权限校验、审批和Excel文件生成仍走实际业务接口。它不能证明真实人脸识别、真实模型理解、真实定位或生产业务效果。

## 启动前准备

从项目根目录执行。需要Windows PowerShell 5.1或7，已经可用的Docker Desktop本地Linux引擎及`mysql:8.4`镜像、JDK、Node.js、本项目`front/node_modules`、`ai-service/.venv`及当前代码构建的`admin/target/boot.jar`。Python环境应包含锁定的AI依赖，具体准备方式见[README](../README.md#本地启动)及AI助手一节。启动器不会安装全局依赖、构建JAR、拉取镜像或下载人脸模型。

如果尚未准备JAR，在本项目已有Maven环境中构建；前端和Python依赖也应按正常开发说明先准备。演示不需要导入原始SQL，不需要真实模型Key、人脸权重或已有`.local/*-secrets.json`。

先确认本机的Docker context名称；示例使用`desktop-linux`。运行中的其他项目和原始数据库不需要停机。默认四个端口必须空闲；占用时启动器拒绝启动，不能通过杀掉占用者来“修复”。可为本次演示显式指定另一组空闲端口。

```powershell
.\scripts\start-demo.ps1 `
  -JavaHome 'C:\Path\To\JDK17' `
  -DockerContext 'desktop-linux' `
  -DatabasePort 13307 `
  -BackendPort 19091 `
  -AssistantPort 8011 `
  -FrontendPort 7001
```

`-JavaHome`填写本机JDK目录；Node.js或Python不能自动定位时，可追加`-NodePath '<node.exe绝对路径>'`和`-PythonPath '<本项目ai-service\.venv\Scripts\python.exe绝对路径>'`。不得将其他项目的Python环境当作本项目环境。启动器只接受本机Docker引擎，不接受远端Docker。

启动器保持前台，按其输出等待就绪后访问`http://127.0.0.1:7001`（自定义端口以实际输出为准）。Java、Python、MySQL、Vite均仅绑定`127.0.0.1`，无公开部署。

每次运行创建新的32位`runId`，资料位于`.local/demo/<runId>/`。启动器会打印文件路径：

- `accounts.json`：本次随机生成的五个合成账号及密码，包含管理员、两个部门主管、两个员工。以`role`和`departmentName`识别角色，不依赖固定用户名。
- `demo-context.json`：本次`month`、历史工作日`businessDate`、合成部门/人员/申请编号及`syntheticFixture: true`。
- `manifest.json`及组件日志：仅供本机恢复与排错，含私密运行配置。
- `vite-env/`：启动器新建的空前端环境目录。不要在这里放`.env`文件；演示配置会拒绝现有配置和重解析路径，前端只使用本轮校验过的本地后端地址。

在本地编辑器查看前两个文件。不要把密码、manifest、整个运行目录、浏览器令牌或导出文件提交到公开仓库、发到聊天或放进公开截图。运行资料被Git忽略，并限制本机文件访问权限。

## 5～10分钟业务演示

### 1. 核对合成补卡与审批依据（约2分钟）

分别用普通窗口和浏览器隐私窗口登录同一部门的员工与主管，账号从`accounts.json`选取。进入“考勤工作台”，选择`demo-context.json`中的月份和`businessDate`。

在员工的“我的月度考勤”查看该工作日，在“申请与审批”查看对应补卡申请和审批历史。初始化已经通过实际接口批准补卡；签到/签退依据应显示“补卡”或`CORRECTION`，能关联申请、批准人和时间。它们是为演示构造的历史时序，不是历史人脸识别结果，也没有覆盖原库记录。

如需现场演示一次新审批：员工在“提交申请”选择一个未来工作日的上午或下午半日请假，填写“合成演示申请”，确认不与已有待批/已批区段重叠后提交。主管在“待我审批”核对后批准；员工刷新申请和对应月份的日结果。初始化没有承诺提供待批申请，不要对已有完整事件重复申请同一动作补卡。

### 2. 核对同口径月报（约1～2分钟）

员工打开“月度报表与导出”，选择本次`month`、范围“本人”，点击“预览月报”。查看人员汇总与每日依据：补卡来源、半日请假、缺卡和规则版本都应有依据。该月若含今天或未来日期，会显示“尚未结算”，不应把统计当作工资出勤。

主管选择其当前部门，管理员可切换两个合成部门。部门统计按当前人员累计，不能把“人天”当作单个员工天数。初始化批准的请假也可在明细中核对。

### 3. Mock对话查询与实际导出（约2分钟）

员工打开“AI助手”，确认持续显示“演示模式，非真实AI”。新建会话，发送下面的问题，将月份替换为`demo-context.json`的`month`，例如`2026-10`：

```text
查询我2026-10的考勤汇总
导出我2026-10的考勤报表
```

第一轮核对事实回执、固定来源与月报预览的统计。第二轮成功只表示导出任务已创建。点击“前往报表中心查看任务”，手动刷新到“可下载”，下载Excel；打开后应有说明、人员汇总、每日明细，且与生成时的可见范围一致。

记下本人的实际任务编号，也可问“查询任务123的状态”，把`123`换成该编号。这里生成的是实际XLSX文件，使用的是合成业务数据；Mock通过不能表述成真实模型效果。

遇到“结果尚未确认”时，点击“恢复原请求”，沿用已保存的问题和编号。运行中只手动刷新，不重建会话、反复换问题或生成第二份任务来猜结果。失败或中断时先核对已有工具回执和导出任务。

### 4. 对照权限边界（约1～2分钟）

切换到另一部门的主管或员工，核对部门选项和日结果只能覆盖其允许范围；普通员工只能看本人月报。主管不能审批另一部门的申请，也不能批准自己的申请。

在另一员工的AI会话中查询前一步员工的导出任务编号，应返回拒绝或无法访问，不得出现对方任务详情、下载链接或文件。部门范围不明确时，Mock可能先澄清；不能将澄清当作服务端越权测试通过的证据。管理员能查询两部门属于其权限，不是越权。

## 停止与收尾

演示结束，在保持前台的启动终端按`Ctrl+C`，等待回收提示。也可在另一个终端使用本轮输出的32位编号：

```powershell
.\scripts\stop-demo.ps1 -RunId '<32位runId>'
```

停止只终止本轮PID/创建时间/可执行路径匹配的进程，校验容器ID与标签后删除本轮无数据卷的临时容器，释放本轮端口。重复停止应安全返回；资源身份不匹配时会拒绝回收，保留线索供人工排查。不要按进程名、端口或容器前缀批量清理。

本轮账号、manifest与日志保留在受保护运行目录，方便核对。再次演示会创建全新运行目录与随机账号，不复用或重置旧运行。原始数据库、已有密钥和其他容器不参与本流程。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 缺少JAR、依赖或本机镜像 | 先按开发说明准备本项目依赖，再启动新一轮；启动器不会自动安装或联网下载。 |
| 端口已占用 | 查清占用服务或显式指定另一组空闲端口，不杀其他项目的进程。 |
| Docker context不存在或是远端 | 使用本机Docker Desktop Linux引擎的实际context；远端引擎会被拒绝。 |
| 助手不是Mock或未就绪 | 核对本轮组件日志与启动结果，保持普通考勤功能可用；不要补入真实Key来绕过演示入口。 |
| 某次请求失败或结果未知 | 查看页面回执，恢复原请求；日志只在本机排查，不公开其中的私密运行信息。 |
| 人脸打卡不可用 | 这是本入口的明确范围。真实人脸录入与识别需按正常开发入口单独配置和验证。 |

设计和资源边界见[独立合成演示环境设计](本地演示环境设计.md)。
