# 人员创建保存失败的事务处理

日期：2026-10-27。目标用户为通过账号管理或人员管理创建员工、主管和管理员的管理员。本轮延续既有事务入口，修复底层保存明确返回false时仍返回成功、可能留下不完整账号或档案的问题。

## 业务流程与范围

创建链路为操作权限检查、账号校验及保存、必要的员工或主管档案保存，最后返回成功。AccountLifecycleService的createUser、createEmployee、createManager已具有Spring事务，但当前忽略档案save的布尔结果；UserServiceImpl.saveUser也忽略底层账号save的结果。仅返回false不会触发事务回滚，现有测试只覆盖档案保存抛异常的路径。

验收目标是：只有账号及所需档案全部保存成功，管理入口才能返回成功；账号保存返回false时停止创建档案，档案保存返回false时回滚本次账号。保留原有抛异常回滚、正常创建、角色和动态操作权限检查。原用户名边界及短占位邮箱修复继续有效。

修改仅覆盖上述管理员创建入口及其共用账号保存步骤，将明确失败转为ServiceException，沿用统一错误响应。复用已有Spring事务，不使用补偿删除、自动重试或新的事务组件。前端、接口结构、数据表和存量数据不变，不连接使用方原始数据库；不扩展所有更新入口或默认关闭的注册流程，也不增加AI写操作。

## 核心风险验证

使用现有MockMvc、真实Spring Service和H2内存库，不Mock saveUser整体流程。只在底层save上注入故障，先真实执行INSERT、在同一事务内确认已写入，再返回false，验证外层事务确实回滚。这是可复现的人工故障注入，不声称真实数据库自然返回了该响应。

- 档案失败：覆盖人员入口的员工、主管，以及账号入口的员工、主管；均返回失败，账号/员工/主管三表数量恢复原值，新账号不能登录。
- 账号失败：覆盖人员入口的员工、主管，以及账号入口的管理员、员工、主管；均返回失败、三表无残留，且两个档案保存入口均未调用。
- 继续运行长用户名、账号关联、密码、权限和原有抛异常回滚测试，并执行完整后端verify；CI继续验证前端、Python、MySQL迁移和两种PowerShell安全检查。
