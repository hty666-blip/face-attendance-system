# 考勤闭环：固定日班

日期：2026-10-26。使用者为员工、部门主管和管理员。保留原技术，Java 统一负责业务，不新增外部服务。

主流程：员工选择签到/签退并扫脸 → 保存不可直接改写的事件 → 按日展示结果 → 员工对缺卡申请补卡或提交日/半日请假 → 有权限的主管审批 → 汇总按批准的事实重新计算，保留申请及状态历史。

本轮范围：全组织固定日班、周末和未来日期的工作日调整、未来生效的规则版本、每日两种动作唯一约束、月度每日结果、日/半日请假、过去30天缺卡申请、审批/撤回及幂等、可复核历史。个人/部门按现有账号、操作权限与服务端部门范围限制。补卡审批沿用records.edit（迁移给内置部门主管角色显式绑定，旧原始事件编辑入口关闭）；请假审批沿用leaveapply.edit。主管不能审批自己；审批时同时复查申请当时部门与当前人员范围。

非目标：夜班、多班次、部门差异规则、工资、加班结算、私密附件、消息推送、完整异步报表、AI 助手及生产部署。尚无私密附件存储，所以本轮申请只收文本原因，不能把证明材料放入共享头像目录。

## 口径与旧数据

- 所有业务日期/时间使用 Asia/Shanghai。新模块初始生效日为部署执行 V003 当日（数据库连接须使用相同时区）；规则起止时间从旧规则复制，后续只能追加明日或更晚生效版本。旧规则编辑入口关闭，防止出现两套权威规则。
- 默认周一至周五应出勤；管理员可配置未来日期为工作日/休息日。过去和今天的规则、日历不可改写；当天首次涉及业务时保留日快照。读取未来日期不提前冻结快照。
- 固定日班要求开始时间早于12:00、结束时间晚于12:00，半日分界12:00；请假按上午/下午计算0.5天，不推算小时数。
- 签到窗口为开始前2小时至结束；签退窗口为开始至结束后4小时（不跨业务日）。允许缺少签到时先签退，以保留真实事件。是否可做该动作由服务端返回，浏览器不能指定他人、业务日或通过状态。
- 每人每天每种动作最多一条有效事件。人脸与补卡共用唯一约束与用户行锁。成功会话可查询原结果，不同会话也不能重复生成相同动作。
- 今天显示进行中，不提前记缺勤；过去缺少应有动作记“待核对/缺卡”，不直接称旷工。宽限分钟只影响是否迟到/早退，异常分钟为超出宽限后的分钟（向上取整）。
- 批准上午假免签到、下午假免签退、全天假免两种动作。请假提交时检查半日范围、倒置和待批/已批重叠。旧自由文本时长无可靠日期，保留旧入口读取与旧审批，但不折算新模块请假；旧入口不再接受新建或员工编辑。新请假开始不早于生效日和今天前30天，结束不晚于今天后366天，单次最多31个自然日。
- 补卡只允许新模块生效后、过去30天内的工作日缺失动作；实际发生时间必须落在当天相应窗口，且没有被已批请假豁免。批准产生来源为CORRECTION的新事件，不覆盖原始事件。已有事件时拒绝补卡。
- 调岗历史无法从旧库还原。新事件和申请保存当时部门；主管读取/审批同时检查当前人员范围与当时部门，不因调入取得其他部门既有记录。无历史归属的旧记录不生成精确的新日结论。过去日期无可靠部门归属的申请记部门0，仅管理员可审批。
- 日结果按保存的日规则与已批准事实即时计算，不另建可能失效的汇总缓存。未来日历变更可以改变尚未发生日期的预计应出勤；过去日结果不因新规则变更而静默变化。

## 接口契约

沿用 `{code,msg,data}`；未登录401、无权403、并发/状态冲突409、业务校验422。新接口仍返回业务code，客户端必须检查。

- `GET /attendance/today` → `{businessDate,serverTime,day,actions:[{action,label,allowed,reason}]}`；action仅IN/OUT。
- `GET /attendance/month?month=YYYY-MM&userId=` → `{month,userId,days,statistics}`，默认本人，限定单月；Day包含businessDate、workingDay、policyId、startTime、endTime、checkIn、checkOut、lateMinutes、earlyMinutes、missingIn、missingOut、leaveDays、status、pendingCount；checkIn/checkOut为事件对象，occurredAt为发生时间、createTime为写入时间。不可见历史日返回RESTRICTED且不附事实。
- `POST /face/challenge {action:"IN"|"OUT"}`：会话绑定服务端业务日与动作；验证请求继续只提交challengeId、imageBase、address。旧无动作客户端由服务端按可用动作选择，且仍服从窗口/唯一性规则。
- `GET /attendance/requests?scope=mine|pending|all&pageNum=&pageSize=` → `{records,total}`；GET `/attendance/requests/{id}` → `{request,history}`。
- `POST /attendance/requests`：共同字段requestKey（32～64位字母数字/横线）、kind（CORRECTION/LEAVE）、reason。补卡附businessDate/action/correctionTime（yyyy-MM-dd HH:mm:ss）；请假附startDate/startHalf/endDate/endHalf（AM/PM）、leaveType（事假/病假/婚假/丧假）。相同用户同requestKey同内容返回原申请，不同内容409；模型/客户端不能指定申请人、部门、状态。
- `POST /attendance/requests/{id}/decision {version,decision:"APPROVED"|"REJECTED",comment}`；`POST /attendance/requests/{id}/cancel {version}`。只允许PENDING转终态；相同决策重试可返回原结果，矛盾或过期版本409。每次状态变更同事务追加历史。
- `GET/POST /attendance/policies`：POST `{effectiveFrom,startTime,endTime,graceMinutes}`，仅管理员且有rules.edit。GET返回已有全局版本。
- `GET /attendance/calendar?month=`；POST `/attendance/calendar {date,workingDay,note}`，只允许未来日期。改动配置需管理员和rules.edit。

## 验收

1. 扫脸明确保存IN/OUT；并发不同会话、重复提交和补卡竞争不产生重复动作，跨日或过期会话拒绝。
2. 补卡/请假从提交到审批、历史、日结果更新有页面及接口链路；他人/非所管部门/本人自审被拒绝。
3. 申请并发决策、创建重复、请假重叠、事务失败回滚有针对性测试；旧历史不被删改或猜测迁移。
4. 今天不提前缺勤，周末/调休、半日假、宽限、历史规则版本计算有测试。
5. V003、新库结构、权限种子、启动说明与交付证据同步。原库不自动迁移；验证使用独立H2与临时MySQL 8.4，使用方原库部署前仍须备份并在副本核对升级与恢复。
