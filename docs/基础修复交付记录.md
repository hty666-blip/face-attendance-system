# 基础修复交付记录

日期：2026-10-23。范围为第一轮基础修复，不包括 AI、本地识别、补卡与完整报表建设。

## 实际变更

1. 移除前后端固定日期限制，跨域来源改为显式配置；移除公开导出、密码重置、用户列表和公告删除的登录绕过。
2. 新增统一 `AuthorizationInterceptor`，检查操作权限；`AccessPolicy` 统一本人/部门范围，并覆盖分页、全量列表、详情、统计与导出。
3. 个人资料仅接受邮箱与头像字段；忽略客户端提交的角色、目标账号、密码及人脸。密码变更使用当前身份，重置仅管理员有权执行，不回传明文新密码；注销只能作用于当前身份。
4. 自助注册默认关闭，启用后也只创建员工。新增密码为8至64位且不超过 BCrypt 的72字节限制；停用不物理删除历史考勤。创建、更新账号和档案使用统一事务入口；新增初始密码、不可改账号的前端提示。
5. 用户 JSON 不返回密码哈希、人脸数据、新密码；用户 Excel 仅四个允许字段。用户下拉仅返回受限的 id/name/role。
6. 请假创建强制当前申请人及“审核中”，员工不能编辑审核字段；主管只能审核所管部门的他人待审核申请。已审核申请不能直接覆盖；状态条件更新阻止重复审批覆盖。
7. 腾讯云凭据改为环境配置、默认禁用；图片去除 Data URL 前缀；数值按 `Number` 读取，服务失败或未配置不写考勤。已登录打卡只比对本人的模板，避免遍历员工产生多次云调用。本轮仍沿用简化的中午划分规则，重复打卡约束留待考勤模块阶段。
8. 文件入口限系统共享图片，下载要求登录，图片重编码与路径检查；前端鉴权加载图片和导出。新旧富文本均做清洗，并通过受限组件展示；本轮不提供私密附件服务。
9. 核心业务表迁移至 InnoDB 的脚本已准备；不自动执行。账号/档案/考勤/权限等高风险批量导入暂停，待后续补齐逐行验证和事务策略后恢复。
10. 修正 MyBatis-Plus 依赖名、仓库 HTTPS、Swagger 扫描路径及 Springfox 与额外端点配置冲突；修复前端组件大小写、未声明变量、加载失败状态和导出鉴权。
11. 新增脱敏建库、种子数据、初始化管理员、环境样例、健康检查、启动说明和 CI。没有升级 Java 语言目标或 Spring Boot 主版本。

## 关键请求链路

- 查询/导出：Bearer → 登录有效性 → 当前账号与操作权限 → `AccessPolicy` 数据范围 → 同一 Service 查询 → JSON 或 XLSX。
- 创建员工：管理员与操作权限 → `AccountLifecycleService` → 校验密码及部门 → 账号写入 → 档案写入；后一步失败时回滚前一步。
- 请假审批：操作权限 → 申请存在及部门范围 → 非本人、待审核 → 只接受审核字段 → 带旧状态条件更新。
- 云端打卡：当前账号 → 本人模板 → 配置及图片校验 → 腾讯云单次比对 → 分数和规则检查 → 写考勤；失败不写记录。

原先没有 Git 历史，修复前源码、配置、上传文件与原始 SQL 已保存在被忽略的 `.local/before-foundation-*.zip` 中。该备份含原始材料，禁止公开；公开仓库只包含修复后的源码与脱敏脚本。

## 已知限制与后续验证

- 当前机器未检测到运行中的 MySQL 服务，未执行真实旧库迁移。需要在 MySQL 8 副本验证引擎变更、旧数据兼容、账号登录、三角色操作及回退。
- 真实腾讯云、摄像头、高德定位没有在这轮端到端联调。没有使用原始凭据发起付费请求，也没有轮换外部账号的密钥。原密钥若有效仍需账户所有者在云端轮换。
- 原始旧库中的弱密码没有批量重写。停用账号档案仍保留；历史记录的前端姓名选择器可能不展示已停用用户，需要在后续考勤历史视图中明确标识。
- 当前查询按现有部门归属隔离，未实现人员调动的历史部门快照；没有多租户隔离声明。
- 共享图片对已登录用户可见；文件系统不是私密证据存储。没有活体检测与可靠位置防伪。图片和特征不能进入聊天模型或公开仓库。
- 审计注解是原有占位，完整的持久化操作审计尚未实现；审批版本、原始打卡事件、幂等和任务恢复在后续阶段建设。
- 未加入登录速率限制、生产监控或依赖全面升级，本轮成果不应被描述为可直接投产。
- 依赖首次下载耗时较长；前端构建有大体积 bundle 提示，后续再按实测拆分。
