# 人脸识别考勤系统

在本科毕业项目基础上持续完善的考勤管理系统，保留 Vue 3 + Spring Boot + MySQL。已完成基础修复，并加入默认在本机运行的 OpenCV 人脸识别服务。AI 助手、补卡与完整报表中心仍在后续计划中。

## 当前功能与技术

- 管理员、部门主管、员工三类角色，部门与人员档案。
- 密码登录、管理员三张样本录入、本人的 1:1 人脸验证打卡、高德地图定位。
- 人脸模板加密、状态查看、撤销、旧照片逐人迁移；打卡会话有效期、重复请求与并发保护。
- 本地检测单人入镜、图片大小、脸部尺寸、清晰度和光线；服务异常有明确提示。
- 请假申请及部门主管审批、公告、考勤与请假统计、鉴权 Excel 导出。
- 后端接口鉴权、本人/部门数据范围、敏感字段隐藏、账户与档案事务。

前端：Vue 3、Vite 4、Element Plus、Pinia、Axios、ECharts。后端：Java 8 语言目标、Spring Boot 2.7.5、MyBatis-Plus、Sa-Token/JWT、MySQL、Hutool/POI。验证构建使用 JDK 17；未迁移到 Spring Boot 3。

人脸计算：Python 3.11/3.12、FastAPI、OpenCV YuNet + SFace，在 CPU 上运行。增加独立进程是为了复用 OpenCV 的检测、对齐和特征提取；Python 不访问数据库、不处理业务权限、不决定是否写入考勤，相关规则仍由 Java 统一负责。本轮未引入 LangChain、向量数据库或模型训练。

## 本地启动

需要 JDK 8 或 17、Maven 3.8+、Node.js 20、MySQL 8，以及 Python 3.11 或 3.12。以下 PowerShell 命令从项目根目录执行。建议先在新库或旧库副本上运行，不覆盖历史数据库。

### 1. 数据库

新建空库（例如 `attendance_dev`，字符集 `utf8mb4`），在该库中依次执行：

```text
database/schema.sql
database/seed.sql
```

新建库结构已经包含本地人脸模板与验证会话表，不需要重复执行迁移。脚本只含结构、基础角色、菜单和规则，不含原毕设的账号、人脸图片、联系方式和考勤数据。不要在已有表的库上重复执行建表与种子脚本。

**旧库先备份，再在副本核对库名与现有结构，按顺序手动执行：**

```text
database/migrations/V001__foundation.sql
database/migrations/V002__local_face.sql
```

已完成 V001 的库只执行 V002。V001 将业务表改为 InnoDB 并修正菜单根节点；V002 新增加密模板与打卡会话表。脚本不会自动运行，也不会自动转换旧人脸。DDL 存在隐式提交，回退应恢复备份，不能依赖事务回滚。真实 MySQL 8 迁移仍需要在使用方的数据库副本验证。

### 2. 准备本地人脸服务

```powershell
# 仅首次生成密钥；已有文件不会覆盖，也不在终端显示密钥。
.\scripts\init-face-secrets.ps1

# 指定本机 Python 3.11 或 3.12；已在 PATH 时可省略参数。
.\scripts\setup-face.ps1 -PythonPath 'C:\Path\To\Python312\python.exe'
```

准备脚本只在 `ai-service/.venv` 安装 `requirements.txt` 锁定的依赖，再显式下载模型。不会安装全局依赖、修改真实数据库或启动服务。重复执行会复用环境并重新检查模型。

模型来自固定版本的 [OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7)，具体文件、大小与 SHA-256 见 `ai-service/models/manifest.json`。模型约 39 MB，首次准备需要联网，下载后必须通过校验；运行服务时不自动下载。权重、依赖环境及临时下载文件不进入仓库，模型许可文件保留在 `ai-service/models/`。

在第一个终端启动：

```powershell
.\scripts\start-face.ps1
```

服务只监听 `127.0.0.1:8010`，单进程、并发限流，不开启自动重载。访问 `http://127.0.0.1:8010/health` 应返回 `status: UP` 及模型版本；`DOWN` 通常表示模型或令牌未准备好。健康端点不表示识别准确率。内部推理接口需要令牌，浏览器不直接调用该服务。

`.local/face-secrets.json` 保存两项独立随机配置：AES-256-GCM 模板密钥 `FACE_TEMPLATE_KEY`、Java/Python 通信令牌 `FACE_INTERNAL_TOKEN`。Java 与 Python 启动脚本读取同一文件，显式进程环境变量优先。此文件被 Git 忽略，Windows 生成时限制文件访问权限。**应将模板密钥与数据库一起安全备份；丢失密钥后，已有模板无法恢复，必须重新采集。** 不要通过重新运行初始化脚本轮换已有模板的密钥。

### 3. 后端

在第二个终端设置数据库环境变量。`.env.example` 仅列出变量说明，Spring Boot 不会自动加载根目录 `.env`。

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/attendance_dev?serverTimezone=Asia/Shanghai'
$env:DB_USERNAME = 'root'
# 密码由启动脚本隐藏输入；也可通过当前进程环境传入。
.\scripts\start-backend.ps1 -BootstrapAdmin
```

仅首次空库需要 `-BootstrapAdmin`，脚本会隐藏输入管理员初始密码；默认账号名 `admin`，可设置 `BOOTSTRAP_ADMIN_USERNAME`。已有管理员时禁止覆盖，之后使用不带该参数的启动命令。

未配置全局 Maven 或默认 Java 版本不兼容时，可增加 `-MavenPath '<Maven目录>\bin\mvn.cmd' -JavaHome '<JDK17目录>'`。可以使用 IDE 自带的 Maven 与 JDK，脚本只设置当前 PowerShell 进程环境。

脚本生成本次运行的随机 JWT 签名密钥。需要重启后保留登录时，自行通过受保护环境配置持久的 `JWT_SECRET`。该登录密钥与人脸模板密钥独立。未使用启动脚本时，需显式提供 `JWT_SECRET`、数据库配置及人脸配置，再运行：

```text
mvn -B -ntp -pl admin -am package -DskipTests
java -jar admin/target/boot.jar
```

后端默认仅监听 `127.0.0.1:9090`。健康检查 `GET /health` 只表示后端可用；登录后 `GET /face/service-status` 另外检查人脸配置与服务状态。接口文档：`http://localhost:9090/swagger-ui/index.html`。业务接口沿用 `{code,msg,data}` 格式，`401` 为未登录，`403` 为拒绝访问。存量前端兼容阶段业务错误仍可能使用 HTTP 200，客户端需检查 `code`。

仅运行人员管理、审批与导出时，可设置 `$env:FACE_ENABLED = 'false'`，此时无需准备 Python 或人脸密钥；人脸录入和打卡明确提示未配置，不会写入成功记录。

### 4. 前端

在第三个终端进入 `front`，将 `.env.example` 复制为 `.env.local`，按需配置服务地址和地图 Key，然后执行：

```text
npm ci
npm run dev
```

访问 `http://localhost:7000`。`VITE_SERVER_URL` 使用 `localhost:9090` 形式。高德浏览器 Key 需在服务方限制来源。使用摄像头需要浏览器权限及安全上下文，本机 `localhost` 可用，远程部署应使用 HTTPS；关闭采集弹窗会释放视频轨道。

### 5. 录入、迁移与打卡

1. 管理员在人员档案中打开“人脸管理”，确认目标员工，正面入镜并依次采集三张照片。保持单人、光线均匀、脸部完整，可轻微调整角度；质量不足时按提示重拍。
2. 本地服务输出特征，Java 加密保存。新录入不保存原始照片，也不通过共享文件接口提供模板下载。成功登记会替换该 Provider 的旧模板并增加版本。
3. 有旧 `sys_user.face` 的员工，可以由管理员逐人发起迁移。迁移失败保留原数据；**成功保存加密模板后，同一事务清除该员工的旧明文照片**。迁移只有一张历史样本，建议随后重新采集三张。迁移前保留安全备份，备份中的旧明文照片不会自动删除。
4. 员工进入考勤打卡，获得绑定本人及模板版本的短期会话，定位后拍摄验证。成功重试返回原记录，不重复写入；网络中断时应重试原请求以确认结果。撤销或重新录入后，尚未成功的旧会话失效。
5. 管理员撤销人脸时，清除该员工所有 Provider 的模板并使未完成旧会话失效；员工需要重新登记才能打卡。停用账号也会在同一事务清除模板和旧照片。员工不能自行替换本人或他人的模板。

## 人脸配置与边界

默认 `FACE_ENABLED=true`、`FACE_PROVIDER=local`、`FACE_LOCAL_URL=http://127.0.0.1:8010`。未配置密钥、模型缺失或本地服务不可达时拒绝录入和验证，**不会自动切到腾讯云**。Java/Python 分别部署时需要单独设计受保护的通信方式，本轮脚本只支持同机回环访问。

`FACE_LOCAL_THRESHOLD=0.45` 是 SFace 余弦相似度的可调整初值，取多张参考特征与当前照片的相似度平均值；清晰度、亮度及脸部尺寸也是工程初值。它们未经过本项目人群数据校准，不能用一次同图比对或 Mock 测试证明识别准确率。更换模型版本、阈值或采集环境后，应使用自愿采集且独立于录入样本的测试集评估误接收与误拒绝。

本轮没有活体检测；照片或视频重放仍可能通过。一次性会话和请求幂等不能代替活体检测，也不限制员工一天发起几次独立打卡。定位来自浏览器上报，尚无可靠位置防伪或地理围栏；现有中午划分考勤规则仍保留。这些能力不能作为可靠防代打卡或生产级考勤合规证明。

腾讯云保留为显式兼容选项，账户所有者需自行确认产品、计费和密钥有效性后设置：

```text
FACE_PROVIDER=tencent
TENCENT_SECRET_ID=...
TENCENT_SECRET_KEY=...
TENCENT_REGION=ap-shanghai
FACE_THRESHOLD=80
FACE_TEMPLATE_KEY=<受保护环境提供的原模板密钥>
```

腾讯云模式需要加密参考图并将比对图片发送给云服务，其质量检查、分值和模板格式与本地模式不同。两种 Provider 的模板互不通用，切换后应由管理员重新录入或从仍存在的旧照片迁移。不能用本地余弦阈值代替腾讯云分值阈值。本轮没有使用旧凭据确认腾讯云状态，也没有真实云调用测试；不会在本地失败后静默上传照片。

自助注册默认关闭；若显式设置 `REGISTRATION_ENABLED=true`，也只允许员工注册。主管和管理员由管理员创建。新增人员必须填写初始密码，不再自动使用 `123`。旧库中的既有弱密码没有被批量改写，应由管理员重置。

## 权限与操作边界

| 操作 | 员工 | 主管 | 管理员 |
|---|---|---|---|
| 记录列表、详情、导出 | 本人且有操作权限 | 本人及所管部门且有操作权限 | 有操作权限的全局数据 |
| 提交请假 | 本人 | 本人（无法自审） | 本人（无法自审） |
| 编辑待审核申请 | 本人内容字段 | 所管部门他人申请的审核字段 | 他人申请的审核字段 |
| 人员、部门、规则、角色、权限管理 | 禁止写入 | 禁止写入 | 仍需相应操作权限 |
| 人脸录入、迁移与撤销 | 禁止 | 禁止 | 需要人员编辑权限 |
| 人脸状态、验证打卡 | 本人且有操作权限 | 本人且有操作权限 | 本人打卡；有权限可查看员工录入状态 |
| 用户选项列表 | 本人必要字段 | 本人及所管部门必要字段 | 在职用户必要字段 |
| 图片上传与下载 | 登录后的系统共享图片 | 同左 | 同左 |

操作权限以数据库中角色授权为准，即使页面按钮被伪造也要经过后端检查。账号和角色状态从数据库重新读取，停用账号、调整角色及撤销权限即时作用于后续请求。模板状态接口不返回照片、向量或密文。

文件入口只支持头像和公告使用的 PNG/JPEG 共享图片：需登录、限大小/像素、重编码、校验路径，前端使用带鉴权头的 Blob 加载。**不支持私密附件或私有人脸档案的文件托管**，不得将其放入该共享图片目录。

账户停用使用逻辑删除，保留档案与历史考勤，同时清除人脸模板和旧照片并使未完成旧会话失效；停用主管前先解除其负责部门。系统内置角色不可删除。有关联人员的部门不可删除。未建完整导入校验前，账号、档案、请假、考勤及权限等高风险批量导入入口已暂停，避免绕过业务约束；页面按钮同步标记不可用。

## 验证

```powershell
mvn -B -ntp verify

Push-Location front
npm ci
node --test
npm run build
Pop-Location

# 已运行 setup-face.ps1 后，在项目根执行。
.\ai-service\.venv\Scripts\python.exe -m pytest -q ai-service/tests
```

后端使用独立 H2（MySQL 模式）测试库，不接触原始数据库，覆盖权限、模板加密、迁移、撤销、会话时效、幂等、并发及事务回滚；业务流程中的人脸 Provider 使用 Mock。Python 单元测试验证接口契约、输入校验和失败处理，前端原生测试检查摄像头生命周期。单元测试不需要下载权重，也不代表真实摄像头、人群精度、定位或腾讯云端到端联调。

H2 验证不代替 MySQL 8 迁移。当前运行环境未检测到 MySQL 服务，未对原库执行迁移。实际验证结果与限制见 `docs/基础修复交付记录.md` 和 `docs/人脸改造交付记录.md`；设计取舍见 `docs/人脸改造设计.md`。

GitHub Actions 保留后端验证、前端测试与构建，并增加 Python 3.12 单元测试。项目依赖、构建输出、上传图片、人脸数据、密钥、本地备份和缓存不进入公开仓库。CI 不访问真实数据库或云人脸账号。
