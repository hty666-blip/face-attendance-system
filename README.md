# 人脸识别考勤系统

在本科毕业项目基础上持续完善的考勤管理系统，保留 Vue 3 + Spring Boot + MySQL 技术。当前版本完成第一轮基础修复；AI 助手、本地人脸识别、补卡及报表中心仍在规划中。

## 当前功能与技术

- 管理员、部门主管、员工三类角色，部门与人员档案。
- 密码登录、管理员采集人脸、腾讯云本人 1:1 验证打卡、高德地图定位。
- 请假申请及部门主管审批、公告、考勤与请假统计、鉴权 Excel 导出。
- 后端接口鉴权、本人/部门数据范围、敏感字段隐藏、账户与档案事务。

前端：Vue 3、Vite 4、Element Plus、Pinia、Axios、ECharts。后端：Java 8 语言目标、Spring Boot 2.7.5、MyBatis-Plus、Sa-Token/JWT、MySQL、Hutool/POI。验证构建使用 JDK 17；未迁移到 Spring Boot 3。

## 本地启动

需要 JDK 8 或 17、Maven 3.8+、Node.js 20、MySQL 8。建议先在新库或旧库副本上运行，不覆盖历史数据库。

### 1. 数据库

新建空库（例如 `attendance_dev`，字符集 `utf8mb4`），在该库中依次执行：

```text
database/schema.sql
database/seed.sql
```

脚本只含结构、基础角色、菜单和规则，不含原毕设的账号、人脸图片、联系方式和考勤数据。不要在已有表的库上重复执行建表与种子脚本。

旧库副本使用 `database/migrations/V001__foundation.sql`，将 MyISAM 业务表改为 InnoDB，并修正菜单根节点。执行前先备份并核对库名；DDL 存在隐式提交，回退应恢复备份，不能依赖事务回滚。该脚本不会自动运行。

### 2. 后端

在项目根目录设置环境变量。`.env.example` 仅列出变量说明，Spring Boot 不会自动加载根目录 `.env`。

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/attendance_dev?serverTimezone=Asia/Shanghai'
$env:DB_USERNAME = 'root'
# 密码由启动脚本隐藏输入；也可通过当前进程环境传入。
.\scripts\start-backend.ps1 -BootstrapAdmin
```

仅首次空库需要 `-BootstrapAdmin`，脚本会隐藏输入管理员初始密码；默认账号名 `admin`，可设置 `BOOTSTRAP_ADMIN_USERNAME`。已有管理员时禁止覆盖，之后使用不带该参数的启动命令。

脚本生成本次运行的随机 JWT 签名密钥。需要重启后保留登录时，自行通过受保护环境配置持久的 `JWT_SECRET`。未使用脚本时必须显式设置它，不提供内置部署密钥。

也可手动运行：

```text
mvn -B -ntp -pl admin -am package -DskipTests
java -jar admin/target/boot.jar
```

后端默认仅监听 `127.0.0.1:9090`。健康检查：`GET /health`，只返回 `UP` / `DOWN`；接口文档：`http://localhost:9090/swagger-ui/index.html`。业务接口沿用 `{code,msg,data}` 返回格式，`401` 为未登录，`403` 为拒绝访问。存量前端兼容阶段业务错误仍可能使用 HTTP 200，客户端需检查 `code`。

### 3. 前端

在 `front` 中将 `.env.example` 复制为 `.env.local`，按需配置服务地址和地图 Key，然后执行：

```text
npm ci
npm run dev
```

访问 `http://localhost:7000`。`VITE_SERVER_URL` 使用 `localhost:9090` 形式。高德浏览器 Key 需在服务方限制来源；使用真实摄像头需要浏览器权限及安全上下文（本机 localhost 可用，远程部署应使用 HTTPS）。

### 4. 人脸服务与账户配置

默认 `FACE_ENABLED=false`，此时打卡明确提示服务未配置，不调用旧密钥，也不会写入成功记录。恢复腾讯云需要由账户所有者确认服务状态后，通过环境提供：

```text
FACE_ENABLED=true
TENCENT_SECRET_ID=...
TENCENT_SECRET_KEY=...
TENCENT_REGION=ap-shanghai
```

本轮未确认腾讯云旧账号的计费、密钥或产品状态；本地 OpenCV 替换尚未实施。普通人员管理、审批和导出不依赖该服务。

自助注册默认关闭；若显式设置 `REGISTRATION_ENABLED=true`，也只允许员工注册。主管和管理员由管理员创建。新增人员必须填写初始密码，不再自动使用 `123`。旧库中的既有弱密码没有被批量改写，应由管理员重置。

## 权限与操作边界

| 操作 | 员工 | 主管 | 管理员 |
|---|---|---|---|
| 记录列表、详情、导出 | 本人且有操作权限 | 本人及所管部门且有操作权限 | 有操作权限的全局数据 |
| 提交请假 | 本人 | 本人（无法自审） | 本人（无法自审） |
| 编辑待审核申请 | 本人内容字段 | 所管部门他人申请的审核字段 | 他人申请的审核字段 |
| 人员、部门、规则、角色、权限管理 | 禁止写入 | 禁止写入 | 仍需相应操作权限 |
| 用户选项列表 | 本人必要字段 | 本人及所管部门必要字段 | 在职用户必要字段 |
| 图片上传与下载 | 登录后的系统共享图片 | 同左 | 同左 |

操作权限以数据库中角色授权为准，即使页面按钮被伪造也要经过后端检查。账号和角色状态从数据库重新读取，停用账号、调整角色及撤销权限即时作用于后续请求。

本轮文件入口只支持头像和公告使用的 PNG/JPEG 共享图片：需登录、限大小/像素、重编码、校验路径，前端使用带鉴权头的 Blob 加载。**不支持私密附件或私有人脸档案的文件托管**，不得将其放入该共享图片目录。人脸模板只通过受控后端接口登记，不通过图片下载接口读取。

账户停用使用逻辑删除并保留档案、历史考勤；停用主管前先解除其负责部门。系统内置角色不可删除。有关联人员的部门不可删除。未建完整导入校验前，账号、档案、请假、考勤及权限等高风险批量导入入口已暂停，避免绕过业务约束；页面按钮同步标记不可用。

## 验证

```text
mvn -B -ntp verify
cd front
npm ci
npm run build
```

后端使用独立 H2（MySQL 模式）测试库，不接触原始数据库。覆盖匿名导出/密码重置、员工与主管数据隔离、个人资料字段越权、请假审核字段越权、密码变更、账号停用、事务回滚、云端失败不落考勤、跨域和角色/部门约束。人脸云端使用 Mock，不代表真实识别成功。

H2 验证不代替 MySQL 8 迁移与真实联调。当前运行环境未检测到 MySQL 服务，因此未对原库执行迁移、未完成真实摄像头或腾讯云联调。验证结果和限制记录在 `docs/基础修复交付记录.md`。

GitHub Actions 配置了后端验证和前端构建。项目依赖、构建输出、上传图片、本地配置、备份及本地工具缓存不进入仓库。
